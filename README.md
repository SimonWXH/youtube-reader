# Build / MyGo

YouTube Reader is a macOS app. It is built with Go 1.27+ and MyGo v0.10.0 native UI (`github.com/egoist/mygo/ui`). There is no frontend, webview, HTML or JavaScript in the app.

## Requirements

- Go 1.27+
- macOS arm64 for the signed `.app` and DMG build
- A YouTube Data API v3 key entered in Settings (local only, never bundled or synced)

## Develop and build

```sh
go tool mygo dev
make test
make build
make dmg
make dmg-path
```

`make build` runs `Scripts/build-helper.sh` to build the standalone helper into `resources/darwin`, compiles the app, and signs `dist/darwin-arm64/YouTube Reader.app` ad hoc with `codesign --force --sign -`. `make dmg` packages that signed bundle and an `/Applications` symlink into a compressed UDZO disk image with `hdiutil`, and `make dmg-path` prints the image path. The build is ad hoc signed and not notarized; there is no Developer ID, Team ID, or stapler step.

## Installation

1. Open the disk image and drag **YouTube Reader** into `/Applications`.
2. On first launch, macOS will block the unnotarized app. Allow it through **System Settings** -> **Privacy & Security** -> **Open Anyway**, or remove the quarantine attribute from the installed bundle with `xattr -d com.apple.quarantine "/Applications/YouTube Reader.app"`.

See [`.github/release-notes.md`](.github/release-notes.md) for the complete first-launch instructions.

## Continuous integration and releases

`.github/workflows/ci.yml` is the pull-request gate: it vets, tests, builds the app and DMG with `make dmg`, and verifies the image at `make dmg-path` on a macOS arm64 runner using the Go version from `go.mod`. Pull requests that change only Markdown files still report the required `verify` check, but skip the build and tests. There is no `push` trigger; after a direct push to `main` or a merge whose tree differs from the tested pull-request head, start CI manually with `workflow_dispatch`.

`.github/workflows/release.yml` runs on pushed `v*` tags. The tag must be exactly `v` plus the `version` in `mygo.json` (for example `v1.0.0` for version `1.0.0`), so prerelease-style tags are not supported while `mygo.json` holds a stable version. Releases follow copyqmac's deliberate prerelease-only policy: the workflow runs `make dmg`, attaches the DMG path reported by `make dmg-path`, and attaches release notes from `.github/release-notes.md` (falling back to GitHub-generated notes only when that file is absent) to a GitHub prerelease. There is no stable-release path. CI runs `make dmg` and verifies the image at `make dmg-path`, so pull requests and releases use the same ad-hoc signed UDZO artifact.

## Features

- OPML import preserving group hierarchy, duplicate channel memberships and channel merge by ID. Imports never delete existing channels. Multiple OPML files can be selected.
- YouTube Data API v3 only for video subscriptions: `channels.list` (batches of 50, and for `id`, `forHandle` or `forUsername` when a subscription is added by link or handle), `playlistItems.list` (three pages maximum and a 30-day cutoff for a refresh, and one 50-upload page per 载入更多 click from a saved page token), and `videos.list` for missing metadata and Shorts detection. No video RSS feeds, no `search.list`, no server.
- Video grid that fills the center pane, with 16:9 remote thumbnails and avatars, two-line titles, unread dots, relative time and Shorts indicators. Channel names on video cards navigate to that channel's filtered view in the app. The column count defaults to 5 and can be set from 2 to 8 in Settings; the cards divide the pane's width after its padding and scrollbar gutter, so the grid fills the pane at every window width. Shorts are hidden by default and can be enabled in Settings. Sizes and styling are described in [Visual design](#visual-design).
- Right-side detail drawer that appears only when a video is selected, with Open on YouTube…, Copy link and Favorite/Unfavorite. It slides in from the right over 240 ms and gives the width back to the grid on close; Escape with the focus in the pane closes it and returns the focus to the grid. Opening a video in YouTube marks it as read; selecting a card, scrolling, filtering and searching do not.
- The main window reopens at the size and position it was last closed with, never smaller than its 960 x 640 minimum, and opens at 1280 x 808 centered on first launch or when the saved frame no longer lands on a connected display. Resizable left navigation, center grid and right detail panes (or a 3-column middle timeline and right reader view in the RSS workspace). Drag the dividers to change their widths; the chosen widths persist in local settings. The sidebar toggles from the toolbar or the View menu. A 54 pt horizontal dock at the top of the sidebar hosts four top-level workspaces: Videos, RSS, Read Later (placeholder), and WeChat Notes (placeholder). Each dock slot displays an icon with a count beneath it; workspaces can be reordered by dragging dock slots, or switched via clicking or Command-1 through Command-4, and the chosen order and active workspace persist in local settings. Each workspace is completely isolated: switching pages hides unrelated elements, while search queries, filters, navigation selections, selected items, and sidebar scroll offsets remain strictly independent across workspaces. In the Videos workspace, the sidebar has Library (All videos, Favorites), the OPML group sections with their channels, and an Ungrouped section for channels in no group (未分组 when the system locale is Chinese); a channel in a group appears only there, and every channel row shows the channel's avatar. A group's channels stay in case-insensitive title order, so a new subscription lands where its name sorts instead of at the end, a number or symbol prefix sorts by code point like any other prefix, and a library saved before this order existed is arranged on the next launch. Group sections start collapsed and each group's fold state persists in local settings across restarts; clicking a group's disclosure chevron toggles its channels tree, clicking the group row itself selects the group and aggregates all of its channels' videos in the grid, right-clicking a group row opens a context menu to rename the group inline and sync it, and right-clicking a channel row opens a context menu to unsubscribe from the channel (取消订阅 when the system locale is Chinese). Unsubscribing confirms with a warning dialog and removes the channel from sync memberships, local store records, and notification preferences, while favorited videos are permanently preserved; if the unsubscribed channel was selected, navigation falls back to All videos. Groups reorder by dragging a group row (disabled during inline renaming): the list takes the new order as the pointer crosses each block, giving the drag up with Escape puts the groups back, and the order persists in local settings. Channels move between groups or to ungrouped by dragging a channel row: dropping onto another group moves the channel there and expands the group, dropping onto the ungrouped area removes it from every group, and hovering over a valid target highlights the row with a soft accent surface, a 1.5 pt accent border, and a "Move here" ("移入此组") callout bubble; single membership is maintained, dropping onto the current group is a no-op, and changes sync immediately and persist to the local store. When all channels belong to groups, starting a channel drag reveals a dashed Ungrouped drop strip at the bottom so channels can always be ungrouped. A fresh import starts the groups in the OPML file's order, a later import appends the groups it adds for the first time in its own file order, and groups that arrive without an import, as from another device sync, join the end alphabetically. All videos, Favorites, group and channel rows show their video counts; the selected sidebar destination (All videos, Favorites, a group or a channel) persists in local settings across restarts and is restored on launch, falling back to All videos when the stored group or channel no longer exists. Up and Down move the selection, Return opens the selected row, and every row paints a focus ring when focused from the keyboard. Channel filter, keyword search and the Unwatched check box apply within the selected group. A fixed 34 pt footer under the list holds one compact 28 by 28 pt plus button, inset 8 pt: its menu offers New Group, which appends a group and puts it straight into the inline rename, and Add Subscription…, which opens the add-subscription dialog. The list gives up exactly the footer's height, so no row is ever drawn under it, including at the window's 960 x 640 minimum. In the RSS workspace, the sidebar has Smart Feeds (All articles with total unread count, Starred with starred count), RSS group sections with their feeds, and an Ungrouped section for feeds in no group. Group sections start expanded or collapsed according to local settings; clicking a group selects it, right-clicking a group row opens a context menu to rename the group inline or delete it, and right-clicking a feed row opens a context menu to rename the feed inline or unsubscribe. New and renamed groups stay unique ignoring case: New Group arrives numbered once that name is taken, and a rename that would repeat another group's name takes a number instead. A library that already holds two same-named groups from an older build still exports two identically named folders. Groups reorder by dragging a group row, and feeds reorder or move between groups and ungrouped by dragging a feed row, with a dashed Ungrouped drop strip when all feeds belong to groups. Feeds that encounter errors during fetching display a visible failure indicator with an error tooltip rather than failing silently. An RSS library with no feeds and no groups draws "No RSS feeds yet" (暂无 RSS 订阅) in the sidebar over one 11 pt sentence, a 28 pt Add RSS Feed primary action and a 26 pt outlined Import OPML… (导入 OPML…) action beneath it. The RSS sidebar footer holds the same compact 28 by 28 pt plus button offering New Group (which appends a group and enters inline rename), Add Subscription… (which opens the add-RSS dialog), and, below a separator, Import OPML… and Export OPML….
- Add subscription: the dialog accepts a channel link (`youtube.com/channel/UC…`), an `@handle`, a bare handle or legacy username, a `UC` channel ID, or a video link (`watch?v=`, `youtu.be/`, `/shorts/`), all read locally first so obviously invalid input, an empty field or a custom `/c/` link costs no API call. It resolves the reference through `channels.list` (a bare name is tried as a handle, then as a legacy username), shows the channel's avatar and name before adding it, and chooses the destination group inside the dialog: the groups, then Ungrouped as an explicit choice, then a New Group… row with an inline 26 pt name field. The picker starts on the group the sidebar has selected, or Ungrouped when the sidebar shows All videos, Favorites or a channel. A channel the library already holds becomes a move: the primary button reads Move and the dialog states it as "This moves A from B to C", while a channel already in the chosen group keeps Add disabled and says so. Adding writes the channel and its group membership to the sync file and the local store, expands the chosen group, and fetches only that channel's metadata and recent uploads in the background; a quota that runs out at that moment is skipped silently rather than undoing the add, and a new channel starts with notifications off, which the dialog states in one line and never toggles. Offline and an exhausted quota block the add with an inline notice naming when to retry (reconnect, or the time the pause ends, the same pause the rest of the app waits for); a channel without a title is never created. Escape closes the group list first and the dialog second, Return submits, and a lookup that lands after the dialog closed is discarded.
- Add RSS feed: the dialog supports dual-mode input, accepting either a direct RSS/Atom/JSON feed URL or a website homepage URL that auto-discovers feed links from HTML `<link>` tags. It resolves the source in the background, displays a preview card with the feed title, description, and available article count, and lets the user choose the destination group inside the dialog (existing RSS groups, Ungrouped, or a New Group… row with an inline name field). Adding persists the feed and group assignment in the local SQLite store and triggers an immediate background fetch. Invalid URLs or unreachable feeds show inline error notices; Escape closes the group picker first and the dialog second, and Return submits.
- RSS OPML import and export: Import OPML… reads one or more `.opml` or `.xml` files, turns their nested `<outline>` folders into RSS groups (a folder's `title` wins over its `text`) and subscribes every feed that carries an `xmlUrl`, rewriting the `feed://` and `feed:https://` schemes other readers write. Feeds match by canonical URL, so a feed the library already holds is skipped, one it unsubscribed earlier is revived in place of a duplicate, and a feed listed under several folders keeps every membership; the same document can list it twice without adding it twice. A folder named like a group the library already holds, in any case, adds its feeds to that group and revives it if it was deleted instead of creating a second one; new groups append to the group order in the file's own order. The import runs off the main thread and answers with a toast naming how many feeds and groups it added or restored, or saying nothing was new because every feed was already subscribed, then fetches the imported feeds in the background so the window stays live however large the file. Export OPML… writes the active RSS groups and feeds to a standard OPML 2.0 document: the head carries the title and dates, one `<outline>` folder per group in sidebar order, and each feed an outline with `type="rss"`, its display title, `xmlUrl` and, when the feed recorded one, `htmlUrl`. Feeds in no group follow the folders at the top level in title order, and unsubscribed or deleted records are left out, so the file re-imports into any reader or back into this one. The commands sit in the RSS sidebar footer's plus menu and in the toolbar overflow menu, where Export OPML… is dimmed outside the RSS workspace, and the File menu carries both: Import OPML… follows the active workspace and imports channels from the Videos workspace and feeds from the RSS workspace, while Export OPML… always writes the RSS library. Neither direction ever touches YouTube channels - the importer writes only RSS records and the exporter reads only them.
- RSS reading view: selecting an article in the middle timeline opens it in the right pane, rendered natively from the article's parsed blocks rather than in a web view, with the feed name and stamped date, a headline of at most three lines, the author, headings, paragraphs, block quotes with an accent rule, fenced code with its language, lists, and inline pictures fitted to the reading column. The header's Open in Browser (在浏览器中打开) hands the original page to the system browser, and Refetch (重新抓取) re-extracts the article's full text in the background and reloads it without disturbing its read or starred state. A 28 pt star beside them shows and toggles the article's star (star, accent-filled while starred), and each starred row in the timeline carries the same filled star beside its feed name, so the Starred smart feed and the count it shows always match what the list marks. The RSS workspace is readable without a pointer: J and K step the timeline one article at a time, opening each in the reader and scrolling its row into view, M marks the open article read or unread, S stars or unstars it, and Command-O opens its original page in the browser. Those keys exist only while the RSS page shows, so the Videos workspace keeps its own keys untouched, and the four single keys stand aside while a field takes typing, so J, K, M and S in the article search field or an inline rename are the letters they type. The body scrolls in a reading column capped at 700 pt and centred with 24 pt gutters, beside a 24 pt paragraph rail on the reader's right edge: one short bar per block, the bar the reading line is in grown and accented while the rest stay thin and muted, spread over the rail so the highlight follows the article's position as it scrolls. Clicking a bar glides the body to the paragraph it shows, landing the paragraph's top on the reading line and growing that bar, while a bar under the pointer grows and opens a light preview to its left that names the block's kind (段落, 标题, 引用, 代码块, 列表 or 图片 when the system locale is Chinese) over its opening 56 characters. An article whose extraction fails, times out or yields less than a paragraph's worth of text (about 100 characters) falls back to the feed's own summary through a one-sentence notice above the body that opens the original page in the browser on click or Return, with the permanent Read the original article link still at the end of the body. A picture that fails to load - an anti-hotlink 403, a 404 or a timeout - never blanks or breaks the reader: its frame keeps the reading column with a bordered placeholder carrying the image's alt text (or Image failed to load when the feed supplies none) and an Open original image in browser link, where a click or Return opens the picture and Space still pages the article. The article list keeps its own stored width (400 pt by default, 260-480 pt), the reader takes the remaining width but never less than 320 pt, and the sidebar yields to those minimums in this workspace; each article opens at its own top, and switching pages restores the reading place.
- Native menu bar that mirrors the toolbar: the App menu carries Settings… at Command-Comma, Command-R refreshes, the View menu toggles the sidebar, and commands that cannot run are dimmed rather than hidden.
- Refresh intervals: Manual, 5, 15 (default), 30 or 60 minutes. Manual never refreshes on its own; the toolbar's refresh control and the Refresh command still do. Automatic refresh is owned by the optional background helper below. An interval stored by an older build stays visible and selectable. Retain at most 30 hours or 400 videos, protecting unread, favorited and backfilled videos.
- Channel history (载入更多): a refresh reads only the last 30 days of uploads, so a channel that posts rarely arrives with a couple of videos or none. A channel's own page offers a quiet "Load 50 earlier videos" (载入更早视频 (50 条)) button under the grid's last row that reads one `playlistItems.list` page of 50 uploads further back, hydrates their durations with one `videos.list` call, keeps only long videos, and commits the page to the local store: two quota units per click, whatever the channel's age. The page token the API returns is saved in the local store, so the next click reads the page before it and no click pays for a page twice; an empty token means the channel's earliest video is loaded and the button becomes the muted line "All earlier videos loaded" (已载入全部历史视频). A channel with nothing in the window draws the empty pane with "Load history videos" (立即抓取历史视频) as its primary action, so an inactive channel is not a dead end. Loading disables the button and names the work; a failure stays readable above it and the first attempt moves on. A backfilled video is stored marked as such, which exempts it from the retention window and the 400-video cap: the reader spent a quota unit on it, so a later refresh never drops it. Repeating a click, or overlapping a refresh, re-stores the same video by its ID without a duplicate row, without resetting whether it was read, and without touching a favorite.
- Offline/failure UX: the last successful data stays visible. For a refresh with content on screen, refresh state lives in one menu bar item and its popover (see [Visual design](#visual-design)); the window repeats none of it, there is no top error banner, and a refresh posts no toast. Offline also disables the window's refresh control with a "You are offline" tooltip, and an open content pane with no cached video names the offline state instead of an empty library. Quota exhaustion pauses refreshes for 24 hours and raises one alert when the pause begins, then shows the Paused state with its resume time in the popover, including a pause already in force at launch (unless no API key is set, where setup owns the panel).
- Single-file Syncthing sync: one JSON file (`~/Library/Application Support/YouTubeReader/youtube-reader-sync.json` by default, configurable in Settings) holds groups/channel membership, read states (any device read wins) and favorites with optional metadata. Writes are read-before-write, idempotent by stable id, and use a dot-prefixed temp file, fsync, atomic rename and directory fsync. `*.sync-conflict-*` copies are merged on load and app-generated copies are removed. A local flock lives outside the Syncthing folder; Settings has "Force take over sync". SQLite, API key, notification preferences, local UI preferences (the main window's size and position, pane widths, video and RSS group fold states, group orders, ungrouped feed order, workspace order, active workspace, the selected sidebar destination and the Settings pane last shown), locks, queues and logs are never synced.
- Settings is a separate 520 x 460 window with General, Backups and Notifications panes, opened from the App menu's Settings… (Command-Comma). The window title follows the active pane, the last pane reopens, edits save as they are made, and Escape closes it. The General pane holds the API key (masked, with a reveal toggle and validation on blur), the refresh interval, Shorts, the grid's column count, the background helper and OPML import; Backups holds the favorites backup path with export, restore and the last export time, the shared sync file, and Erase local favorites behind a system confirmation; Notifications holds per-channel consent and, when macOS refused notifications, a button that opens the relevant System Settings pane.
- Favorites backup: Settings has a configurable full backup path and writes a standalone favorites-only JSON (no API key, read history, video payload or synced state). Export writes the path atomically; Restore is an independent entry that reads a chosen favorites JSON and merges by stable video ID, with newer local favorites winning.
- Local SQLite store (`videos.sqlite`) uses WAL and a five-second busy timeout. Each refresh commits channels, videos and revision in one transaction; notifications post only after commit. A channel's history page commits its videos and then its page token, so an interrupted click reads the same page again rather than skipping it.
- Local system notifications: per-channel toggles default OFF; Settings' Notifications pane groups subscriptions like the sidebar with per-group batch toggles and an Ungrouped section, and Enable All turns them all on, whichever view the main window shows. One notification per opted-in channel per refresh with new-video count and newest title. A video counts as new only while the local store has never held it, no earlier refresh announced it and it has not been read; announced videos are remembered for longer than the 30-day uploads window, so the 30-hour/400-video retention limit cannot make the same video alert again an hour later. Retention still decides what the store keeps, so a count can name a video its 30-hour or 400-video limit drops from the grid, and the first open of a store written by an older build seeds the announced records from the videos it already stored. Clicking a notification opens that channel's filtered view. MyGo IDs route app clicks, including a click that launches the app. Notification preferences and announced-video records are local only.
- Background refresh: the standalone helper can be registered as a user LaunchAgent (RunAtLoad + StartInterval) from Settings, and its interval follows the refresh interval chosen there; Manual installs no helper, and choosing Manual removes an existing login item. A stale helper started under Manual performs no refresh. While the app is running, the helper hands its notifications to it over a local Unix socket in the data directory (`notifications.sock`), so macOS attributes them to YouTube Reader and a click activates the app on that channel's view; the app reads the refresh that hand-off committed, so the clicked channel shows the videos that refresh retained locally. With the app closed, or when the app could not open its socket, the helper writes pending notification plans to `notification-pending.json` and launches the app bundle in the background with `--notify-only` (`open -g -j`), which delivers native notifications under YouTube Reader's identity with channel click routing without opening a window or stealing focus. It performs the full YouTube Data API refresh, commits results in SQLite, posts notifications, and writes an atomic JSON handoff consumed by the app on next launch. The app holds the local flock while open; helper shared-JSON writes are queued in SQLite and drained on the app's next launch.

## Visual design

The main window frame is the app's own: a hidden-inset title bar leaves the traffic lights inside a 52 pt toolbar with a sidebar toggle, a centred 13px Semibold title, and borderless 28 pt refresh and overflow controls on the right; below it, a 44 pt filter strip holds the 160 pt channel menu, the 200 pt search field, the Unwatched check box and a right-aligned 11px tabular count, tightening at narrow widths (matched by a 44 pt search, unread and count strip in the RSS workspace). The standalone Settings window uses the same toolbar title style in its own 52 pt bar, with a 40 pt pane strip below it and a scrollable form body of a 140 pt label column beside the controls. The three main-window panes share one token vocabulary in `ui/theme.go` and `ui/typography.go`: warm neutral surfaces (`#f7f7f5` / `#ffffff` light, `#191a1c` / `#25272b` dark), a single blue accent, and re-derived dark colors with small elevation steps instead of inverted light values. Spacing follows a single 4 pt ladder (4/8/12/16/20/24/32, extended to 40 and 48). The sidebar is 260px wide by default and resizable with the other panes between 220px and 320px, remembering its width; the detail pane is 340px by default and resizes from 280 to 480px; in the RSS workspace the article list is 400pt by default and resizes from 260 to 480pt while the reader takes the remaining width, no less than 320pt, and its text column is capped at 700pt. At the top of the sidebar, the 54 pt workspace dock hosts 46 pt slots with 18 pt icons and 11px counts. Navigation and group fold rows are 28px with 2px gaps, channel rows are 34px with 24px avatars, sidebar glyphs use the accent, and video cards keep 18px channel avatars. Each scrolling pane keeps an extra 20 pt below its last row so it clears the window edge, and the grid reserves a 20 pt trailing gutter so its scrollbar sits beside the detail divider with an 8 pt gap from the last card. The add-subscription and add-RSS dialogs are in-window modals: a 420 pt panel on the surface token, raised at a new L2 elevation (offset 24 pt, blur 48 pt, spread -12 pt) over a `ModalScrim` backdrop, with a 1 pt border, a 12 pt radius and 20 pt of inner padding, and every block sized on the same 4 pt ladder: a 15 pt Semibold title, a 28 pt link field, a 48 pt resolved-channel card, a 28 pt group picker whose list rows are 28 pt, a 26 pt inline new-group field, and a right-aligned 28 pt Cancel and Add pair. It is 272 pt tall in its initial state, 286 pt with the two-line not-found error, 300 pt with a quota or offline notice and 306 pt with a channel card, plus 30 pt while the inline name field shows. The type vocabulary is 13px/18px body text, 13px/18px Semibold card titles, 13px/18px Semibold Muted sidebar section headers, and 11px/14px Medium tabular counts; empty panes use the 15px/20px Semibold title, the 13px/18px body sentence, a 32 pt SF Symbol and a 28 pt primary action, all from those roles. Controls expose default, hover, focus, active, disabled, loading, error and success faces, with a visible focus outline and a reduced-motion fallback. Motion uses three timed transitions through `cubic-bezier(0.22, 1, 0.36, 1)`: 120ms for interaction colour, 180ms for popovers, and 240ms for the detail pane's width, which switches instantly when Reduce Motion is on; there is no `transition: all`, animated height/top/left, tracked caps, or gradient chrome. Video cards use 16:9 remote thumbnails that fall back to a real placeholder, with two-line titles and an 11 px Medium footer with tabular figures showing the unread dot, channel name and relative time; card height is the width times 9/16 plus 76 pt. Monogram avatars stand in when a channel has no avatar URL, while its picture loads, or if the picture fails. A selected card draws a 1 pt accent stroke with a 2 pt 24% accent halo and sets its title in the accent colour; keyboard focus adds a separate 2 pt focus ring. The detail drawer repeats the same tokens and actions so the center grid and right pane read as one surface.

Every content-pane state is part of the shipping view, not a mockup. First launch is a 32 pt SF Symbol over a 15 pt Semibold title, one 13 pt secondary sentence and one 28 pt primary action, with variants for a missing API key, no imported channels, an empty destination, an empty channel, no favorites and filters that match nothing; no variant draws an illustration or sample cards. A channel's page carries the history control as a 28 pt outlined footer button centred under the grid's last card, in the empty pane's own button style; its disabled face says a page is loading, and its loaded face is the muted 12 pt line where the button was, so the pane never shifts. With no channel imported, the sidebar says "No channels yet" beside a 28 pt "Add channel…" action, and the detail pane stays absent until a video is selected. A refresh with nothing cached draws a skeleton of 12 neutral cards in the real grid's card geometry, with no animation and no spinner of its own; the toolbar's refresh control holds the one unlabeled spinner and the strip above the grid carries Cancel. A refresh with content on screen keeps the content and reports itself in the toolbar control and the status popover, never by reloading the pane. A failed refresh with nothing cached draws the error inline: what failed, what to check, the recorded reason with the API key redacted, and a Retry button, as a live region rather than an alert dialog; only the quota pause raises an alert. Offline keeps cached content, disables the refresh control with the "You are offline" tooltip and draws the offline state in a pane with nothing cached, while the status popover keeps its Retry. A thumbnail that cannot load stays a neutral 16:9 frame with a play glyph and a tooltip, never a broken-image icon. Refresh failures never post notifications, and relative copy is rebuilt by the status surface's 30 second clock. Refresh status is a menu bar item and one popover, and with content on screen it is not part of any window. The item is an 18 pt template image - `checkmark.circle`, `arrow.triangle.2.circlepath`, `pause.circle`, `wifi.slash`, `exclamationmark.triangle`, `key.fill` or `arrow.clockwise` - so its shape says the state and macOS tints it for the menu bar and for both appearances; text joins the icon ("Set up", "Not refreshed", "Paused", "Offline", "Refresh failed") only while the reader needs attention, and the hover text repeats the popover's own copy. MyGo's `TrayOptions.Icon` takes PNG bytes plus `IconIsTemplate` and has no SF Symbol API, so the seven shapes are committed 36 px (18 pt at 2x) template PNGs in `assets/status`, drawn from SF Symbols by `Scripts/status-icons.swift` and embedded in the binary. The popover is 320 pt wide with automatic height, capped at 420 pt where its rows scroll; it is a focusable flyout with the system window shadow, a 1 pt `Border` hairline, a 12 pt radius drawn from `RadiusWindow`, and a 12 pt diamond arrow whose centre stays on the item as AppKit slides the panel back into the work area. Inside, the heading is 13 pt Semibold with a 12 pt body line and the rows are 12 pt with tabular values, all on the tokens and the type roles (`PopoverTitle`, `PopoverBody`). There is no close button: an outside click or Escape closes it, one panel exists at a time, and nothing opens over it. A quota pause raises a native alert when it begins while the app is running; a pause already in force at launch opens as the Paused state with its resume time instead of a second alert, except when no API key is set, where setup owns the panel. Copy is fixed per state: "Set up YouTube Reader" with Open Settings… while the API key is missing, "Not refreshed yet" with Refresh now, "Up to date" with "Last refresh 2 min ago", "Refreshing", "Refresh paused" with when refreshes resume, "Offline" with "Showing cached videos" and Retry, and a failure that quotes the recorded message with Retry or Open Settings…, except a rejected key, which says the repair instead. A quota pause disables every refresh action - the popover button, the window toolbar, the overflow item, View > Refresh and the empty grid's Refresh now - and shows when refreshes resume in the popover; a failed message is stored and displayed with the API key redacted. Relative times come from one function in `status.go`, and the popover is rebuilt every 30 seconds so they stay true.

## Known limitations

- Click routing depends on macOS delivering a notification click and on notification permission being granted. A notification the app posts itself, whether from its own refresh or from helper delivery (via local socket or background `--notify-only`), carries its channel's ID and routes a click to that channel, including on a cold launch where macOS delivers it. Physical cold-click verification for helper notifications remains manual.
- Residual hand-off race: if the main app exits in the millisecond gap after the helper hands a notification over and before the app shows it, that notification is not shown. The helper never waits on the display, so a background refresh is never blocked by the app.
- Notification permission must be granted in macOS System Settings the first time a notification is posted. When macOS refuses one, the Notifications pane says so and offers Open System Settings…; the refusal is remembered in local settings.
- The helper implementation has local vet/tests and app-level CI validation; LaunchAgent registration and live notification delivery still need manual verification on the captain's Mac. The LaunchAgent is installed per user and uses absolute paths resolved from the app bundle.

To confirm the disk image contains the install shortcut, attach it and check that `Applications` is a symlink to `/Applications`:

```sh
DMG=$(make --no-print-directory dmg-path)
MNT=$(mktemp -d)
hdiutil attach -readonly -nobrowse -mountpoint "$MNT" "$DMG"
ls -l "$MNT/Applications"
hdiutil detach "$MNT"
rmdir "$MNT"
```

MyGo automation can drive the built app for UI verification:

```sh
go build -tags e2e -o /tmp/ytreader-e2e-app .
MYGO_AUTOMATION=/tmp/ytreader-e2e.sock /tmp/ytreader-e2e-app
mygo-automation open --socket /tmp/ytreader-e2e.sock
mygo-automation snapshot -i
mygo-automation screenshot /tmp/ytreader.png
```

The `e2e` build also honours `YTREADER_APPEARANCE=light` or `dark` so both appearances can be captured on a machine whose system appearance is one of them. The override lives only in the build-tagged `e2e.go`; release builds never compile it.
